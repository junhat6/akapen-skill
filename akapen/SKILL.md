# akapen — 実装前の赤ペン先生

作る前に1案を人へ見せ、人の赤（回答・訂正）を受け取ってから作るための確認ゲート。

- **Input**: 見せたい1案（UI配置・設計・方針、または長文原稿）と、決めてほしい論点
- **Output**: `./akapen/<topic>-01.html` と、画面から届く `【赤ペン回答】` テキスト
- **対応**: Codexを標準経路とし、Claude Codeでは同じHTML・Python資産を互換経路で使う
- **Cloud**: 正式対応外。ローカルファイルやブラウザを利用できる環境で使う

## 最重要禁則

- **`【赤ペン回答】` が届く前に実装を始めない。** 待機中に無関係な作業を進めるのはよい
- **検証で生成した回答を、人の回答として扱わない。** 送信テストは一時ディレクトリのコピーで行い、人が使うシートの回答ファイルへ書き込まない
- **同じ議題に判断が残るなら、回答後も赤ペンを続ける。** 後続の発言で重要な未決定が分かった場合も、人に再起動を頼まず次稿を出す。未出題の仕様を agent の仮定で Issue や実装へ確定しない
- **赤ペンを質問票にしない。** UIや画面が対象なら、現物のスクリーンショットか忠実なDOM再現を載せる
- **見た目が異なる選択肢は両方を絵にする。** 回答フォームにも同じ絵を載せる
- **事実を人へ聞かない。** 各問に `file:line` または実行結果を示し、人には好み・優先度・トレードオフだけを決めてもらう
- **問いは3±1問、最大4問。** 未選択はお任せとして推奨案で確定できる形にする
- **正解が一意で自己検証できることを聞かない**
- **長文を要約シートへ変形しない。** 原稿そのものを指摘・添削の対象にする
- **ファイルや実装を自動でcommitしない。** commitは人が明示的に依頼した場合だけ行う

## モードを選ぶ

| モード | 対象 | 人がすること | Asset |
|---|---|---|---|
| **標準** | UI配置・設計・方針の1案 | 問いへ回答し、全体コメントと赤ピンを付ける | `assets/sheet-template.html` |
| **指摘** | 記事・README・長文レポート。直すのはagent | 原稿の段落や選択文字列へ指摘を付ける | `assets/shiteki/kit-template.html` |
| **添削** | 人が長文を直接書き換えたい | HTML内で本文を編集し、完成形を返す | `assets/tensaku/build-sheet.py` |

人が「指摘・注文を返す」なら指摘、「本文を書き換える」なら添削、それ以外は標準を使う。添削モードの問いは0問。

## Skillディレクトリを解決する

このファイルが置かれているディレクトリを `<skill-dir>` とする。実行時に提示された `SKILL.md` の絶対パスから求め、`${CLAUDE_PLUGIN_ROOT}`、`$CODEX_HOME`、固定のホームディレクトリを前提にしない。以降のassetとreferenceは必ず `<skill-dir>` からの絶対パスで参照する。

## 手順

1. **現物を把握する** — 既存UIはスクリーンショットかコードから忠実に再現する。長文モードは原稿を凍結する
2. **モードを選ぶ** — 上の表で決める
3. **スタンドアロンHTMLを保存する**
   - 標準: `assets/sheet-template.html` を使い、`references/paper-spec-v3.md` の規約で埋める
   - 指摘: `assets/shiteki/README.md` を読み、原稿HTMLへkitを組み込む
   - 添削: `python3 "<skill-dir>/assets/tensaku/build-sheet.py" <記事.md> <label> "<タイトル>" -o ./akapen/<topic>-01.html`
   - どのモードでも `./akapen/<topic>-01.html` を残す。自動commitはしない
4. **問いを圧縮する** — 各問を、問い1行、各選択肢の利点と代償、判断に必要な実測、未選択時の推奨が揃った自己完結カードにする。添削は省略
   - UIの案では、画面の形だけでなく、使う人が何をしやすくなるかまで比較する。操作の速さ、初見での分かりやすさ、次の操作を迷わず予想できるか、既存画面との一貫性などから、その論点で実際に差が出る軸だけを選ぶ。詳しくは `references/paper-spec-v3.md` の「UI案の比較軸」を参照
5. **試問する** — `references/preflight.md` に従い、会話を継承しない別のsubagentへシートだけを渡す。最大2巡。添削は省略
6. **リンクを提示する** — ブラウザやタブを勝手に開かず、人が開く経路を選べるようにする
   - **標準はローカル中継**: `python3 "<skill-dir>/assets/akapen-serve.py" open ./akapen/<topic>-01.html` を実行する。中継を起動・再利用して URL だけを出力する。応答の末尾に、実際に出力された URL の Markdown リンクを置く。例: `[赤ペン先生（第1稿）を開く](http://127.0.0.1:8765/review-01.html)`。タイトル・稿数・ポートは対象に合わせ、例を固定値として使わない
   - **ローカル環境で使う**: エージェントとブラウザを同じ端末で使う。別端末やクラウドから同じ localhost URL を開けるとは限らない。ポート公開・SSH転送・ネットワーク設定は自動実行しない。クラウド環境は正式対応外。
   - **file:// 貼り戻し**: Pythonが無い、中継を起動できない場合は、絶対パスと `file://` URLを提示する。OS の `open` / `xdg-open` 等は実行しない
   - **明示された場合だけインライン**: 人が会話内表示を求め、対応する Codex surface と `visualize` skill が利用できる場合は、同skillと `references/codex-visualize.md` に従う
7. **人の合図を待つ** — リンクとともに「ブラウザで [送信] したら、この会話で『回答しました』と送ってください」と案内して現在の応答を終える。待機スクリプトや定期確認を実行しない
   - 中継: 人の合図が届いたら `python3 "<skill-dir>/assets/akapen-serve.py" read ./akapen/<topic>-01.html` を一度だけ実行して回答を読む。exit 3 なら [送信] の成否を確認してもらい、次の合図を待つ。古い回答は `read` が除外する
   - インライン: [送信] で `【赤ペン回答】` がfollow-upとして届くので、その本文を読む
   - 貼り戻し: [貼り付ける文章を作る] で得たテキストを入力欄へ貼ってもらい、その本文を読む
8. **反映し、未決定を確認する** — `references/reply-format.md` に従って読む。未選択は**出題済みの問いに限り**推奨案で確定する。回答や同じ議題の後続発言から、成果の採否を左右する未決定の仕様が見つかったら、事実を自分で調べた上で次稿を作り、手順4〜7を繰り返す。先に Issue や実装へ仮定を固定しない。設計が変わる訂正や再往復では `<topic>-02.html` など次の番号を使い、捨てた案は取り消し線で残す
9. **終了する** — 判断に必要な未決定がなくなったら、中継を使った場合は `python3 "<skill-dir>/assets/akapen-serve.py" stop ./akapen` を実行する。HTMLは判断記録として残す。終了後でも同じセッションで重要な未決定が判明したら、次稿で再開する

## 赤ピンの読み方

回答先頭の `赤① (x78% · y30%) <訂正文>` は、人が提案領域 `#akSheet` に置いたピン。座標は場所の近似で、訂正文を正とする。シートへagentが先に置いた注記の①②③とは別物として扱う。

## Gotchas

- 同じディレクトリの複数シートは1つの中継を共有する。回答ファイルはシートごと。`read` は最後に `open` した後の回答だけを読む
- 回答を読む前に中継を止めない
- `file://` では [送信] ではなくコピー経路になる。クリップボードが失敗したらtextareaから手動コピーする
- 下書き保存用キーはシートごとに一意な固定文字列にする。`crypto.randomUUID` は使わない
- radioの `name`（`q1`, `q2`, …）とscript内の質問定義を同期する
- 指摘・添削の往復中は原稿を変更しない。変更する場合は回答後に `-02.html` を作る
- 会話内表示で `Visualization unavailable on this device.` が出たら、保存済みHTMLをローカル中継で開き、実際の回答URLを案内する。HTMLを作り直さない
